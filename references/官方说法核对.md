# 官方说法核对（2026-10-10）

安装和库外读写里那些做法的依据。Codex 文档已从 developers.openai.com 跳转到 learn.chatgpt.com。本机版本：Codex 命令行 0.159.3；Codex App 26.1007（自带的引擎 0.162.0-alpha.17.2，和命令行不是同一个版本）；Claude Code 2.1.283；Node 24.16（脚本按 Node 18 以上写）。

标记：**官方** = 官方文档原文写明；**本机** = 在作者的 Mac 上实测；**程序内文字** = 从本机 Codex 安装包里读到的界面文字（知道按钮叫什么，没在界面上逐个点过）；**推断** = 由官方说法推出，没实测；**未核实** = 查不到或没测。

本机实测的办法：临时 HOME + `codex debug prompt-input`。这条命令离线就能输出新会话里模型实际看到的内容（全局规则、Skill 清单、沙箱模式），不用登录，不碰真实的 `~/.codex`、`~/.agents`。

## Claude Code

| 问题 | 结论 | 依据 |
|---|---|---|
| 用户级 Skill 放哪 | `~/.claude/skills/<名字>/SKILL.md`，本机所有项目可用；个人的优先于项目里的同名 Skill | **官方**：[Skills](https://code.claude.com/docs/en/skills) |
| 装了要不要重启 | 会自动发现改动；会话开始时还没有的顶层 skills 文件夹，要 `/reload-skills` | **官方**：Skills |
| 全局规则 | `~/.claude/CLAUDE.md`，对本机所有项目生效；它里面的 `@` 导入不弹确认 | **官方**：[Memory](https://code.claude.com/docs/en/memory) |
| HTML 注释 | 读 CLAUDE.md 时会去掉块级 `<!-- -->` 注释再交给模型。所以两行标记模型看不到，但中间那段照常读，也不影响脚本认标记 | **官方**：Memory（2026-10-10 读原文核对） |
| 和 AGENTS.md 的关系 | 没有 CLAUDE.md 时读 AGENTS.md；有 CLAUDE.md 时读 CLAUDE.md，建议写一行 `@AGENTS.md`；上级文件夹的 CLAUDE.md 也会读 | **官方**：Memory |
| Windows 位置 | `~/.claude` 就是 `%USERPROFILE%\.claude`；可用 `CLAUDE_CONFIG_DIR` 换位置 | **官方**：[Settings](https://code.claude.com/docs/en/settings) |
| 默认权限模式 | v2.1.283 起，命令行和 VS Code 的交互会话默认是**自动模式**：另一个模型（分类器）替你审核动作。手动模式（`default`）下，改文件、跑命令都先问 | **官方**：[Permission modes](https://code.claude.com/docs/en/permission-modes)（2026-10-10 读原文核对；本机正是 2.1.283） |
| 自动模式下读外面的文件 | 第一次读工作文件夹外面的文件会弹四选一。选 “No, and block reads outside the working directories from now on” 会把 `permissions.blockReadsOutsideWorkingDirectories` 写进用户设置，以后所有会话、所有模式都读不了外面；要恢复就 `/add-dir` 或删掉这个设置 | **官方**：Permission modes |
| 自动模式下改外面的文件 | 工作文件夹里的改动自动放行；外面的交给分类器决定，不一定弹窗 | **官方**：Permission modes |
| 附加文件夹 | 启动时 `--add-dir`、对话中 `/add-dir`、设置里 `permissions.additionalDirectories` | **官方**：[Permissions](https://code.claude.com/docs/en/permissions) |
| `CLAUDE_CONFIG_DIR` | 官方原文说它搬走 “All settings, session history, and plugins”。脚本按“CLAUDE.md 和 skills 也一起搬走”处理（推断）。它也能写在 `~/.claude/settings.json` 的 `env` 里，那时安装脚本拿不到 | **官方**：[env vars](https://code.claude.com/docs/en/env-vars)（二手资料转述）；“连 CLAUDE.md、skills 一起搬”是**推断** |
| 网络共享路径 | Windows 上 `\\服务器\共享` 不能当工作文件夹，先映射盘符 | **官方**：Permissions |

## 由此定下的做法

1. Codex 的 Skill 装 `~/.agents/skills/boss-kb/`；Claude Code 装 `~/.claude/skills/boss-kb/`。两份复制，不用软链接。
2. 全局规则：Codex 写 `$CODEX_HOME/AGENTS.md`（有不为空的 override 时两份都写）；Claude Code 写 `~/.claude/CLAUDE.md`（设了 `CLAUDE_CONFIG_DIR` 就写那里）。只改带标记的那一段；不是 UTF-8 的规则文件不改。
3. 安装时那句话点名“打开 SKILL.md、用自带的安装脚本、别用别的办法装”，避开 Codex 自带的 skill-installer。安装直接申请带权限运行。
4. 库外项目默认**能读、写要授权**：写之前就预告弹窗；不授权就把内容贴在对话里，默认不在当前项目存文件。常写的项目，把知识库“添加文件夹”进项目。
5. 全局规则只写短短一段，不导入整份知识库地图；加“问到自己的客户、项目先去知识库找”和“只听老板在对话里说的”两条。
6. 教“用知识库根目录开项目、选信任”：知识库不是 git 仓库时，从子文件夹打开读不到根目录的 AGENTS.md；不信任是只读。

## 未核实（用之前最好自己试一遍）

- **Codex App 界面上的信任提示**：按钮文字已从安装包读到（见上表），命令行引擎也实测了“信任 = 可写、不信任 = 只读”。没在界面上实际点过；点了“以受限模式打开”以后怎么改回信任，没测。
- **Codex App 的授权弹窗**：四个按钮的文字已读到（见上表）。改知识库文件、跑安装脚本时各出现哪几个按钮，“允许此对话”管多大范围，没在界面上实测。
- **“不选项目”的新对话**：用哪个文件夹当工作区、有什么权限，没测。本 Skill 不用它当验收。
- **Windows 上的具体位置**：`%USERPROFILE%\.agents\skills`、`%USERPROFILE%\.codex\AGENTS.md` 是按“`$HOME` 在 Windows 就是用户文件夹”推出来的，没在 Windows 上实测。
- **Windows 自带沙箱读工作区外的知识库**：会不会放行，没测。这一条决定 Windows 上第一次安装和库外读写能不能走通。
- **Windows 手工安装的 PowerShell 追加写法**、`Select-String` 离线检查：都是推断。
- **Mac 的“文件与文件夹”权限弹窗**：知识库或下载来的 boss-kb 文件夹在“文稿”“桌面”、iCloud 云盘时，Codex App 第一次读会不会弹、拒绝后报什么，没测。
- **Codex App（桌面版）里怎么点名 Skill**：`$` 还是 `@`，各版本可能不同。
- **iCloud 占位文件**：新系统的“未下载”文件文件名不变，沙箱里读它会自动下载还是失败，没测。访达菜单叫“保持下载”还是“立即下载”，按系统版本不同，没逐一核。
- **Windows 上 Node 是否都装好**：脚本要 Node 18 以上（还要搭老板工作台的，boss-workbench 要 22.18 以上，一起装好）；没有 Node 时按 `安装与全局规则.md` 的“全局规则那一段” 手工装。
