# 已有资料与旧库升级

原则：**不搬家，只写地图。** 先读、出清单、确认映射，再只补缺的。确认之前完全只读。

老板让你接入，就是授权你为了建库读相关资料；这不等于授权你改写、公开或搬动它们。老板勾了“不读”的文件夹，连读也没有授权。

## 接入已有资料：11 步

**最小接入（时间不够时先停在这里，比如只有一两个小时）**：体检结论到“工作台能跑”就可以先去搭工作台。“工作台能跑”要四样：必读四份；建库档案的“类型画像”；建库档案的“老板最关心”；至少 1 个客户（建库快照里一行、或一份客户或客户分组档案）或 1 个项目。
- 做第 1—5 步；
- 再把必读四份按原有材料写成“待确认”（正文链接原文件），客户层 README 写好建库快照；按原有材料和第 2、10 题写好建库档案的“类型画像”“老板最关心”，拿不准的句尾标“（AI 推断，待确认）”（照第 8 步列清单，老板说“确认”再写）；
- 跑 `check.mjs --stage connect`，看“体检结论：……”那一行，到“工作台能跑”就可以去搭工作台；
- 补问、复述、跑通真实任务记进建库档案“下次补访”，之后再做。

0. **先讲隐私三件事、问第 0 题**（和快速建库第 1、2 步同样的说法）：文件在本地，AI 处理时内容会发给模型服务商；哪些东西不放进来。顺便问一句用不用 Obsidian 看这个库（文件夹里已经有 `.obsidian` 的不用问）。答案先留在对话里，第 4 步建好接入采访记录后补记，第 8 步写进 `02-关于我/边界.md`（复述后标已确认）。
1. **只读摸底**，分两步：
   - **1a 只看目录**：只列顶层和第二层的文件夹名、每个文件夹里有几份 `.md`，不打开任何正文，已有的 `README.md`、`AGENTS.md` 也先不开。文件夹名里有 日记、私人、个人、家庭、家人、孩子、健康、体检、病历、财务、账本、工资、税、银行、账号、密码、证件 的，标“建议先别看”。`.obsidian`、回收站、缓存不列。
   - **1b 请老板勾选**：每个文件夹三选一——**不读**（AI 不打开、不搜、不记文件名）/ **只读**（可以读，不改不移）/ **正常接入**。标“建议先别看”的，老板没回答就按不读。最后问一句“还有没有不要我看的地方”。老板没提到的、不敏感的文件夹，第 3 步确认方案时按“正常接入”念给他认。老板说不读的，先建议他自己把这个文件夹挪到知识库文件夹外面，这最稳，因为 AI 工具搜文件时还是可能扫到；不想挪的，第 4 步用 `--exclude` 登记，之后不打开、不提炼。

   勾完，先读已有的 `AGENTS.md` / `CLAUDE.md` / `README.md` / 索引页（不读文件夹里的照样不开），再按建库目标挑着读正文，不通读；跳过密码、密钥、证件、大附件。1a、1b 大概这样问（虚构的例子）：

   ```text
   AI：我先只看了目录，没打开任何文件。顶层有这些（括号里是 .md 份数）：
       客户资料/（23）  报价/（4）  项目/（9）  灵感/（40）  日记/（210）  家里的事/（12）
       “日记”“家里的事”看名字像私人的，我标了“建议先别看”。
       每个请你选一个：不读（我不打开、不搜、不记文件名）/ 只读（可以读，不改不移）/ 正常接入。
   老板：日记和家里的事别看。报价只读，我还在改。其他正常。
   AI：好。日记、家里的事最稳的是你自己挪到这个文件夹外面；不挪，我就登记成“不读”。
       报价登记成只读；客户资料、项目、灵感正常接入。还有没有不要我看的地方？
   ```
2. **出四类清单和对应方案**，每条写来源文件（待确认、冲突的，确认时一次问一个主题：“我从 [文件 A]、[文件 B] 看到：你现在……这还对吗？A. 对，直接用 B. 大体对，要补几句 C. 过时了，以你这次说的为准”）：
   - 已知：来源清楚、仍然有效，直接复用；
   - 待确认：可能还对，但太旧、没日期，或会影响重要判断；老板原有材料里写的规则也放这里；
   - 冲突：两处说法不一样（如价目表起价 1.5 万、随手记写“低于 2 万不接”），不替老板选；
   - 缺失：资料里确实没有。

   清单里另外列两样，写清原文位置：
   - 客户，不管放在哪：一个文件一个客户的；用 `#客户`、`tags: [客户]`、`type: client` 这类标签散在各处的；Notion 导出的 CSV 一行一个的。
   - 日记、项目文件里还没做完的 `- [ ]`、`- [/]`。

   Obsidian 的模板文件夹（`Templates` 这类，以及正文带 `{{` 的文件）不是客户、不是待办，不提炼。

   对应方案：每个现有文件夹归三类之一——对应哪一层 / 只读（可以读，不改不移）/ 不读（不打开、不搜、不记文件名）；老板还在写的笔记文件夹归只读；再写哪些层要新建。库里已经有收件箱、附件、原件这类文件夹的，先用 `--map` 对过去（如 `99-原始材料=附件`、`00-收件箱=Inbox`），只新建确实没有的层；新建前，把“会多出哪几个顶层文件夹”列给老板看。
3. **请老板确认对应方案**，明确说：不会移动、改名、覆盖、删除什么；标“不读”的文件夹不打开、不列文件名、不进原件清单；会新增什么——每个对应文件夹里一份 README（或 README-知识库.md），加上必读入口文件（基本情况、协作偏好、生意总览、近期要事，放在对应层里）；他原来的 `AGENTS.md`（有的话）只在末尾追加一段。老板不同意往原有 `AGENTS.md` / `CLAUDE.md` 追加：说清后果（Codex 和工作台都读不到这张地图，工作台暂时搭不了），在建库档案开头写 `入口: 暂缓`，其余照做；体检会提醒“入口没接上”，老板同意后，在知识库里再跑一次 `init.mjs --update-agents`（不用再带 `--map` 这些参数，脚本会按建库档案的目录对应补上地图，并删掉“入口: 暂缓”）。第 0 题（哪些东西不放进来）在第 1 步看目录之前就问，答案先留在对话里。第 1—3 步的原话先留在对话里，第 4 步建好接入采访记录后马上补记进去，并注明“补记”。
4. **先预览再搭**：
   ```bash
   node "<本 Skill 文件夹>/scripts/init.mjs" "<知识库>" --map "04-客户=客户资料,03-生意=我的资料" --readonly "报价,笔记" --exclude "日记" --update-agents --dry-run
   ```
   （老板说用 Obsidian 加 `--obsidian`；文件夹里有 `.obsidian` 会自动按 Obsidian 写法，老板说不用就加 `--plain`。）
   `--map`、`--readonly`、`--exclude` 带了任一个，都按就地建图建（建库档案写“就地建图”、建原件清单和建库快照，体检用 `--stage connect`）；原有文件夹一个都对不上层、只登记了只读或不读的，也是这样。
   把要追加进 `AGENTS.md` 的全文给老板看（dry-run 输出里有），并说明里面“我和我的生意”“跟我说话”两处要问完才填，填的时候只改这一段。（原来就有 `AGENTS.md` / `CLAUDE.md` 的要带 `--update-agents` 才看得到追加的全文；没有的不用带。）老板同意后去掉 `--dry-run` 再跑一次；不同意追加的，去掉 `--update-agents`，按上面“入口: 暂缓”办。脚本还会生成 `01-AI协作/原件清单.md`，记下老板每份原有文件的哈希，以后体检逐份比对。脚本会：建缺的层；在对应的文件夹里只新增一份 README（文件夹里本来就有 README 的，改写成 `README-知识库.md`）；建库档案写好“就地建图”、目录对应表和空的接入清单；`--exclude` 的文件夹在目录对应里记成 `原有·不读`、地图里写“<文件夹>（不读）”、不进原件清单，并追加进根目录的 `.ignore`（给搜索用，对 Codex 搜索是否生效还没实测）；建一份空的接入采访记录。
5. **把第 2 步的四类清单写进建库档案的“接入清单”**，冲突同时写进“冲突”。
6. **补问**：已知的合成一道确认题一次问完（“我从你的资料里看到这几条，哪条不对？”）；待确认、冲突逐条问；缺失的按 `采访题.md` 快速版的顺序问，已有答案的题跳过。每问一题，原话追加进接入采访记录。第 8 题（判断样本）照问，并追问“这条以后都这样吗？”
7. **一屏复述**，请老板改。
8. **列文件清单（每行写拟定的确认和隐私），老板说“确认”再写**：
   - `02-关于我/边界.md`：第 0 题和第 11 题划的线，复述后标已确认。
   - 工作台每次必读的四份照常新建：`02-关于我/基本情况`、`01-AI协作/协作偏好`、`03-生意/生意总览`、`06-项目/近期要事`；放在对应层的文件夹里，正文链接老板的原文件。
   - 客户层 README 写好 `## 建库快照`（名称、类型、分组、阶段、联系人、上次联系、下次跟进、文件），工作台靠它读原有的客户文件。第 2 步列出的客户一家一行，“文件”列写原文的相对链接；CSV 里的客户，“文件”列写那份 CSV 的链接和那一行的名称。
   - 第 2 步列出的没做完的待办，抄进 `06-项目/近期要事.md`，每条后面写“来源 <链接>”，原文件不动。
   - 各层 README 的索引列出原有文件，写清“类型”（客户、项目、产品、规则……）。
   - `AGENTS.md` 地图直接写现有文件夹名，如“客户资料（客户）”；只读文件夹写“报价（只读）”；不读的写“日记（不读）”。
9. **跑通一个真实任务**（如给一个在跟的客户写跟进草稿），只用库里的东西，写明用了哪些文件；产出不写进库。做完马上在建库档案“已完成”写“跑通真实任务：……”。
10. **体检**：
    ```bash
    node "<本 Skill 文件夹>/scripts/check.mjs" "<知识库>" --stage connect
    ```
    按 `结构与规矩.md`“写完就体检”的分法处理：自己写出来的格式问题修到没有；老板原有文件没有元信息的提醒是正常的（每个原有文件夹各一条）；原件清单报改了、少了、改名了，先查是谁动的，不要为了过检查去改清单；内容缺口记进“下次补访”，不硬凑；疑似密钥、证件号、手机号、银行卡号先停下问老板。接入以后老板自己改自己的文件，平时体检只会提醒，不算错。
11. **收尾**：建库档案“下次补访”写最要紧的缺口；告诉老板以后新材料丢 `00-收件箱`，他原来的文件夹照常用。然后做**新对话验收**（老板做，AI 替不了）：请老板在这个知识库项目里点“新对话”，不要在当前对话里问，粘这句：“先别打开任何文件，直接说你现在读到的规矩和地图：知识库有哪几层、我是谁、哪些东西不能放。”原来就有 `AGENTS.md` 的，再加一句“再说说隐私那几条和地图的最后一行”，用来查追加的那段有没有被截掉：Codex 读入口文件有总长度上限，默认 32 KiB，含全局规则。截掉了，就把细则挪进 `01-AI协作/README.md`，把 `AGENTS.md` 缩短（只缩 Skill 写的那段；老板自己写的部分要缩，先问他）。它答不出，或先去打开 `AGENTS.md` 才答，先查是不是用知识库最外层的文件夹开的项目、信任提示有没有选“信任”。通过后在建库档案“已完成”加一行“入口验收：新对话里说得出地图”。

老板还在用的只读文件夹（比如还在写的笔记）：接入收尾时里面的文件有变化只提醒，不算错；老板说“是我自己改的”，可以用 `init.mjs --refresh-originals <文件夹>` 重新登记。

**接好了的标准**：老板原有文件的原内容零改动（老板同意后，`AGENTS.md`、`CLAUDE.md` 只在末尾追加一段，体检按原件清单只比原来那部分）；入口接上了（没写 `入口: 暂缓`）；每个对应层有 README，索引写清原有文件的类型；客户层有建库快照；必读四份都在；老板的价目表、产品介绍在索引里登记过就算“有产品”（在只读文件夹里的，用 `../报价/2026报价单.md` 这样的链接登记在对应层的索引里，类型写“产品”）；冲突都记下了；跑通过 1 个真实任务；`--stage connect` 没有 error；新对话里说得出地图。

补问时老板连着 3 题都说“以后再说”，就把剩下的缺口列成一屏让他勾，勾了以后再说的写进“下次补访”，不逐题追。

## 就地建图的规矩

- 老板原有的文件不改、不移动、不补元信息，也不在末尾追加；新的往来另起一份 `<客户名>-往来记录.md`（类型 往来记录）。
- 原有文件夹里已有 README 的保留，层说明写进 `README-知识库.md`。
- 只读文件夹：不放 README、不对应层、整理收件箱时不移动它里面的东西，但地图里必须有一行。老板还在写的笔记文件夹也登记成只读，别把它当收件箱去“整理”。
- 只读 ≠ 不读：只读的可以打开、引用（用到时在对应层的索引里链过去），只是不改不移；不读的不打开、不搜、不列文件名、不进原件清单，提炼时整个文件夹跳过，地图里只有一行“<文件夹>（不读）”，建库档案“目录对应”记成 `原有·不读`。
- 接入清单里的“已知”合成一道确认题，老板认了才标已确认；没表态的事实照用，标待确认；原有文件本身不补“确认”，读的时候按 `结构与规矩.md`“老板原有的文件”那条用：事实照用、写明原文和修改日期，规则当待确认。
- 原有材料的日期没写年份：按上下文推断的可以写完整日期，正文注明“年份推断”，文件保持“待确认”；推断不出就写“未知”。原有材料的日期比今天还晚的，记进“冲突”问老板。

## 其他几种情况

| 情况 | 做法 | 地图写在哪 |
|---|---|---|
| 资料很大或在别处（作品原文、网盘、旧硬盘） | **外挂只读**：原文留在原处；作品索引、资料地图记路径 | `AGENTS.md` 地图加一行“库外，只读”；`99-原始材料/资料地图.md` 写清每处是什么 |
| Notion、飞书、其他笔记软件 | 先导出（Notion：导出 Markdown & CSV；飞书：先手动导出成 Word 或 Markdown 文件；命令行工具要另外安装、企业版常要管理员开权限，建库时不装、不要求开通，老板主动要再说）。整包放进 `99-原始材料/导入-<来源>-<日期>/`，原样不动；先登记进 `99-原始材料/资料地图.md` 和接入清单，用到哪一层再提炼，不承诺分批整理 | 建库档案的“## 导入批次”记一行 |
| 已经是 Obsidian 库 | 按上面的 11 步就地建图；不动 `.obsidian` 设置；老板的双链照用。init 看到 `.obsidian` 会自动按 Obsidian 写法建（建库档案写 `编辑器: Obsidian`），新写的文件之间也用双链 | `AGENTS.md` 地图、建库档案“目录对应” |
| 已经用 00—99 编号的旧库 | 按编号一一对应，01-AI协作 照常新建 | 同上 |

注意：读库外路径要看 AI 有没有权限，有问题就请老板把资料复制进知识库，或在 Codex 里授权。放在 iCloud、网盘里的文件可能只是占位、没下载到本机，AI 读不到；先请老板右键那个文件夹：Mac 选“保持下载”（老系统叫“立即下载”），Windows OneDrive 选“始终保留在此设备上”（菜单名按系统版本可能不同，没逐一核实）。

## 旧版知识库升级（`格式: 老板知识库/1`）

（试用：v1 没有公开发过，只有早期内部用的旧示例。照下面做完，体检还会把旧的 `知识库说明.md` 当笔记报缺字段；旧 `AGENTS.md` 里的两套入口脚本不会自动处理，要按第 2 步问老板删。这两处还没修好；先给老板看计划，别承诺一次升完。）

旧版的特征：根目录有 `知识库说明.md`，里面一张“类别 | 位置 | 状态 | 一句话”的表；文件夹是 `关于我/`、`生意/`、`资料/`、`原始材料/`。体检脚本看到它会直接提示“请先升级旧库”。

升级做法（先给老板看计划，确认后再动）：

1. 默认按就地建图：
   ```bash
   node "<本 Skill 文件夹>/scripts/init.mjs" "<知识库>" --map "02-关于我=关于我,03-生意=生意,04-客户=生意/客户,06-项目=生意/项目,05-方法与判断=资料,99-原始材料=原始材料" --update-agents --dry-run
   ```

2. `知识库说明.md` 的地图搬进 `AGENTS.md` 的地图；“还缺什么”“建库进度”搬进建库档案。旧 `AGENTS.md` 的“知识库规则”段是旧版 Skill 维护的。先追加 v2 标记段，跑通 `check.mjs --stage connect`，再问老板删不删旧段。原件清单只记到旧段开头之前，所以删旧段不算改老板的文件；删之前，体检会一直提醒“旧版知识库规则段还在”。至少要删掉“先读 知识库说明.md”“同步更新 知识库说明.md”这两行，不能留两套入口。

## 不做的事

- 不自动迁移、合并、改名、删除；任何搬动都要单独列清单、逐项确认。
- 不把旧笔记当成现在的事实：当前角色、项目状态、价格、对外计划，优先确认；稳定的经历不因为旧就作废。
- 不把 `私密` 内容复制进内部或可公开的文件。
- 不打开、不搜、不记录标“不读”的文件夹；老板自己的文件夹由老板自己挪，AI 不替他挪。
