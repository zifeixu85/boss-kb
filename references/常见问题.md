# 常见问题

## 权限

### Codex 说“没有权限”，写不进知识库

这是 Codex 的保护，不是坏了。

- 项目打开时点了“信任文件夹”：Codex 只能改当前项目文件夹里的东西（再加临时文件夹），知识库在外面，改之前会弹窗问你。读一般不受影响。
- 点了“以受限模式打开”（没信任）：整个项目是只读的，连当前项目也写不了（本机实测）。点错了请帮你装的人改（Codex 会把“不信任”记进它的设置文件，怎么改回来还没实测）。

当场处理：见 `库外读写.md 的“写入细则”` 第 7 节——要么这次选“允许一次”，要么先把内容贴在对话里，带回知识库项目。

### 读都读不到，报 “Operation not permitted”

Mac 的隐私保护：知识库或下载来的 boss-kb 文件夹放在“文稿”“桌面”“下载”或 iCloud 云盘里时，Codex 第一次去读，系统会弹窗问“想访问文稿文件夹”。点了“不允许”，之后读文件就报这个错，长得和 Codex 的保护一模一样（推断，没逐一实测）。

去“系统设置 → 隐私与安全性 → 文件与文件夹”，找到 Codex（或 Claude、终端），把“文稿 / 桌面 / iCloud 云盘”打开，再把 Codex 退出重开。

### 把知识库加进项目（经常要写回时）

| 用什么 | 怎么做 | 管多久 |
|---|---|---|
| Codex App | 项目菜单 → 编辑项目 → 添加文件夹 → 选知识库文件夹 | 这个项目一直有效。官方说法：附加的文件夹都能读、能改；但 AGENTS.md 和 Skill 只从主文件夹自动发现，所以知识库的规矩还是靠本 Skill 去读 |
| Claude Code | 对话里输入 `/add-dir <知识库路径>` | 这次对话 |
| Claude Code | 在 `~/.claude/settings.json` 的 `permissions.additionalDirectories` 里加知识库路径 | 一直有效。老板或帮你装的人自己改，AI 不替你改设置文件 |
| Codex 命令行 | `codex --add-dir "<知识库路径>"` | 这次运行 |
| Codex 设置文件 | `~/.codex/config.toml` 里给工作区加可写文件夹（旧写法 `sandbox_workspace_write.writable_roots`，新写法“权限配置”的 `workspace_roots`） | 一直有效。两种写法不能混用，改错了 Codex 可能起不来。没把握就先别改，请帮你装的人确认后再动 |

不建议为了写知识库把权限切到“完全访问”：那样什么都不拦了，AI 写错地方也没人提醒。

### 安装时 Codex 弹出授权，问能不能运行

正常。安装要往你的用户文件夹（`~/.agents/skills`、`~/.codex/AGENTS.md`）里写，这些地方在项目外面。看一眼它要运行的是 `node .../install.mjs`，选“允许一次”（英文界面是 Allow once）。

Codex App 的弹窗有“允许一次”“允许此对话”“始终允许”“拒绝”。**别选“始终允许”**：选了以后，同类命令在任何项目里都不再问你。命令行版 Codex 对应的是“Yes, and don't ask again for commands that start with …”，也别选。

### Claude Code 读知识库时弹窗问能不能读

新版 Claude Code（2.1.283 起）默认是“自动模式”。第一次读当前文件夹外面的文件时，会弹一个四选一：

- 选 **“Yes, and keep allowing any reads outside the working directories”**（允许，以后读外面的文件都不再问）。
- **千万别选** “No, and block reads outside the working directories from now on”：它会写进你的设置，以后所有项目都读不了知识库。
- 选错了：在对话里输入 `/add-dir <知识库路径>`；或请帮你装的人删掉 `~/.claude/settings.json` 里的 `permissions.blockReadsOutsideWorkingDirectories`。

改知识库里的文件：手动模式会先弹窗问；自动模式由它的安全检查决定，可能直接写，也可能拦下。所以本 Skill 不管哪种，都先列计划、等你说“确认”。不想每次问，用上一节的 `/add-dir` 或 `additionalDirectories`。

## 装完没反应

### 新对话里 AI 还是不知道我的知识库

按顺序查：

1. 是不是**新开**的对话？旧对话不会重读全局规则。还不行就把 Codex 整个退出再打开。
2. 运行 `node "<下载来的 boss-kb 文件夹>/scripts/install.mjs" --status`：看 Skill 装没装、规则里记的是哪个路径、那个文件夹还在不在。
3. Codex 里输入 `$`（有的版本是 `@`，命令行里也可以输 `/skills`），看列表里有没有 `boss-kb`；Claude Code 里输入 `/` 看。没有：Skill 没装到位，重新运行安装。
4. 设置文件夹里有 `AGENTS.override.md`？有内容时 Codex 只读它。`--status` 会提醒；重新运行安装会两份都写。
5. 设了 `CODEX_HOME` 或 `CLAUDE_CONFIG_DIR`？脚本按它们装；如果你是在另一个终端、另一个账号里运行的，路径会对不上。
6. 直接点名试一次：“用 $boss-kb 查一下我的知识库里有哪些客户”。点名能用、不点名不用，说明 Skill 说明没被匹配上，把这个情况告诉帮你装的人。
7. 帮你装的人可以用 `安装与全局规则.md` 里“给帮忙安装的人：离线检查新对话看不看得到”那一节的办法，看新会话到底读进了什么。

### 出现了两个“老板知识库”

旧位置 `~/.codex/skills/boss-kb/` 和新位置 `~/.agents/skills/boss-kb/` 各有一份。多半是 AI 用了 Codex 自带的“装 Skill”功能，装到了旧位置。用下载来的 boss-kb 文件夹里的这份重新运行安装，脚本会问过你之后把旧的挪进备份。

### 安装脚本说规则文件“不是 UTF-8”

你的 `AGENTS.md` 或 `CLAUDE.md` 以前是用 PowerShell 或老记事本存的，编码不一样。脚本为了不把它弄成乱码，这次没改。请帮你装的人用记事本打开它，“另存为”时编码选 UTF-8，再运行一次。

### 知识库搬家了、改名了

用新路径再运行一次安装：`node "<下载来的 boss-kb 文件夹>/scripts/install.mjs" --kb "<新路径>"`（先加 `--dry-run` 看一眼）。只会换掉规则里那一行路径。

### 我用示例知识库跟着做的，怎么换成自己的

建好自己的知识库以后，在自己的知识库项目里说：“知识库换成这个文件夹，重新运行老板知识库的安装（install.mjs --kb）。”预演会提醒“规则里原来记的是示例知识库”，你说换就行。

## 打开方式

### 从知识库的子文件夹（比如 `04-客户`）打开了项目

知识库一般不是 git 仓库（一种管版本的工具），这时 Codex 只读当前这一层的 `AGENTS.md`，读不到根目录的规矩。

- 正确做法：用知识库**根目录**开项目，弹出“信任此文件夹吗？”时点“信任文件夹”。
- 已经开了：本 Skill 会先往上找到知识库根目录、主动读一遍根目录的 `AGENTS.md`，所以照样能用；但建议换回根目录开。
- Claude Code 没这个问题：它会读上级文件夹的 `CLAUDE.md`。

### 点“信任文件夹”之前看一眼

选了“信任”，Codex 会加载这个文件夹里的项目设置（`.codex/`）和项目 Skill（`.agents/skills/`）。用老板原有文件夹接入的知识库，如果里面有从别处拷来的 `.codex` 或 `.agents` 文件夹，先问帮你装的人再点信任。点开头的文件夹默认看不见：Mac 访达里按 `Command + Shift + .` 显示。

### 在知识库项目里，还要按库外读写的规矩办吗

不用：在知识库根目录开的对话，知识库自己的 `AGENTS.md` 已经自动读了，按它和本 Skill 的 SKILL.md 办。选了“信任”的知识库项目，改知识库一般不用额外授权（本机实测：信任后可写）；如果也弹窗，选“允许一次”。整理、体检、补访用老板知识库 Skill（boss-kb）。

### 这次不想用知识库

直接说“这次不用知识库”。

## 云盘和路径

### 知识库在 iCloud 里，AI 读不到、很慢、说文件不存在

iCloud（还有 OneDrive、网盘）为了省空间，会把不常用的文件只留一个“占位”，用到才下载。AI 读到占位时可能失败或卡住。

- Mac：在访达里右键知识库文件夹，选“保持下载”（老系统叫“立即下载”）。也可以在“系统设置 → Apple 账户 → iCloud → iCloud 云盘”里关掉“优化 Mac 储存空间”。
- Windows 的 OneDrive：右键知识库文件夹，选“始终保留在此设备上”。
- 运行 `find_kb.mjs` 会提醒知识库在不在云盘里；老系统的 iCloud 占位文件（`.xxx.icloud`）它会数出来。
- 打开了“文稿与桌面”同步到 iCloud 的 Mac：路径看起来就是 `~/Documents`，`find_kb.mjs` 认不出它在云盘里，但同样会有占位的问题，照上面设“保持下载”。
- 工作台的程序和数据库别放云盘里（工作台 Skill 会处理）。

### 怎么拿到知识库的完整路径

- 最省事：把知识库文件夹直接拖进 Codex 的对话框。
- Mac：访达里选中文件夹，按住 Option 右键，选“将……拷贝为路径名”。
- Windows：资源管理器里右键文件夹，选“复制为路径”（Windows 10 要按住 Shift 再右键）。复制出来带引号，没关系，安装脚本会去掉。

### Windows 路径要注意什么

- 路径长这样：`C:\Users\张三\Documents\林总的知识库`。反斜杠 `\`、中文、空格都可以，命令里整个路径用英文双引号包起来。
- 路径末尾别带 `\`：`"C:\...\林总的知识库\"` 里的 `\"` 会被当成“引号本身”，后面的参数全跑进路径里，脚本只会报“找不到这个文件夹”。
- 在 PowerShell 里运行：`node "C:\Users\张三\Downloads\boss-kb\scripts\install.mjs" --kb "C:\Users\张三\Documents\林总的知识库"`。
- 命令里别用 `~`：PowerShell 不会把它展开给 node，会报“找不到模块”。用 `"$HOME\..."` 或直接写完整路径；cmd（命令提示符）里两样都不认，只能写完整路径。（`--kb` 后面的 `~` 没关系，脚本自己会展开。）
- “文档”文件夹被 OneDrive 接管时，真实路径是 `C:\Users\张三\OneDrive\文档\...`，以“复制为路径”拿到的为准。
- 网络共享路径（`\\服务器\共享`）别当知识库：先映射成盘符，或者放回本机。
- 在 WSL（Windows 里的 Linux）里用 Codex 的，路径写法是 `/mnt/c/Users/...`，和 Windows 写法不一样；不建议用 WSL。

## 写入

### AI 写错了，或者写到不该写的地方

- 本 Skill 只追加、都标“待确认”，回知识库整理时可以不采纳。
- 想撤回刚加的那一行：直接说，AI 先列出要删哪几行，你说“确认”再删。
- 不确定改了什么：问“刚才往知识库写了哪几处”，AI 要列出完整路径。

### 内容只贴在对话里了，怎么收回知识库

回知识库项目，把那段贴进去，说：“把这段收进收件箱，整理一下。”要是你让 AI 存成了交接文件，就说：“把 <交接记录的完整路径> 收进收件箱，整理一下。”或者自己把文件拖进知识库的 `00-收件箱`，再说“整理一下收件箱”。整理完，项目里的那份可以删。

### 换电脑、团队成员也要用

每台电脑各运行一次安装，路径填那台电脑上的知识库位置。

环境变量 `BOSS_KB_PATH` 只在全局规则没记路径时才用：规则里记错了，设它也压不过；从程序坞打开的 Codex App 也读不到终端里设的变量。帮你装的人排查时，用 `find_kb.mjs --kb "<知识库>"` 直接指定。
