# 收件箱、复盘与体检

## 一份材料怎么走

```text
分流  AI 先认材料是什么、说的是谁，按下面 (a)—(d) 走；只有认不出的才进 00-收件箱
  ↓
整理  读材料 → 分出 事实 / 已决定 / 待定 / 我的推断 → 列出要写到哪几层、写什么 → 老板确认
      → 写入（每条带来源）→ 原件移到 99-原始材料（移动前问）
        （不移的话，工作台和每周复盘会一直把它当成没整理的）
  ↓
调用  做任务时：地图 → README → 文件；需要核对时回 99
  ↓
写回  任务做完，把老板采用了什么、结果怎样写回去（往来记录、判断样本候选、发现）
```

分流的四种：

- **(a)** 能对上已有客户或项目的聊天、纪要、转写：直接在那份文件的“往来记录”末尾追加，行末标“（待确认）”，来源写原件路径；原件原样新建到 `99-原始材料/聊天与通话/`（原件已经在收件箱里的，移过去之前先问）；在 `01-AI协作/变更记录.md` 末尾记一行（日期｜材料｜写到哪｜怎么撤回）。没有这份就新建：类型 变更记录，表头 `| 日期 | 材料 | 写到哪 | 怎么撤回 |`，只追加。
- **(b)** 订单、平台导出、经营数据、待办、排期：不进知识库，交给工作台导入。工作台还没装，就告诉老板先留着，不放进收件箱。
- **(c)** 签约、回款、报价、交期、补偿、对外承诺，以及要改价格、规则、“关于我”、已确认内容，要新建客户或项目的：不管多确定，都先列清单等老板确认。一份材料里 (a)、(c) 都有，按 (c) 走。
- **(d)** 认不出类型或归属的，才放进 `00-收件箱`，等老板说“整理一下”。

写回时，AI 出的稿、老板真正拿去用的、用过之后结果如何，三样分开记；稿子写出来了，不代表老板点了头。

## 整理新材料（老板说“整理一下”）

init 把这套步骤写进老板库里的 `01-AI协作/任务手册/整理新材料.md`，两边意思一致；这里是给 Skill 自己看的说明。

0. **分流**：收件箱里实际有的、直接给到对话里的材料，先按上面 (a)—(d) 分。(a) 直接追加进往来记录、记进变更记录，在第 9 步报告里说一声，老板说撤就撤；原件在收件箱里的，移走前照样问（第 8 步）。(b) 告诉老板交给工作台。(c) 和 (d) 从第 1 步起列清单、等确认；拿不准是 (a) 还是 (c) 的，按 (c)。第 6、7 步的列清单、等确认，只用于 (c) 和 (d)；(a) 直接追加，在第 9 步报告里说。
1. **列实际文件**：按 `00-收件箱` 文件夹里实际有的文件列，不只看 README 的表；表里没有的（工作台、库外 Skill 新放的）一并列出，整理完补进表。一份一行：哪天、谁给的、说的是谁、一句话。只整理文字稿：录音、视频请老板先转成文字稿再放进来；截图先请老板复制文字，复制不了再由 AI 读图转写，读不清的不猜。已经被往来记录当来源引用过的（以前整理过、原件没移走），不重写，只问能不能移原件。
2. **认人**：一份一份处理。先认出说的是哪位客户、哪个项目；认不出就问老板，不猜。老板写给自己的需求和想法，不找客户。
3. **分四类**：
   - **事实**：发生了什么、原话。
   - **已决定**：双方说定的。会议纪要里只算老板或负责人当场拍板、或在场的人都说同意的，写清谁拍板、哪天前。
   - **待定**：“考虑一下”“下周开会定”；有人提议、还没人拍板的也算，写清谁提的、在哪一段（有逐字稿的带时间戳）。待定不写成已决定，不进近期要事。
   - **我的推断**：AI 的理解，标出来。

   会议里的三种，举例：

   ```text
   老板说“春节礼盒就定两款”                 → 已决定（老板当场拍板）
   运营提议大促加送一款赠品，老板说“再看看” → 待定（运营提议，没拍板）
   “等对方财务给了预算再定档位”             → 待定（等对方的数字）
   ```
4. **特别找出**：老板口头答应的事（给谁、什么、哪天前）；客户的顾虑和决策信号；和已有规则或判断样本对不上的地方（写成一条“待确认的发现”，不替老板改规则）。答应的价格、份数条件、赠品、交期，逐条对产品价目（`03-生意/产品与服务`）和这类工作的判断规则（`05-方法与判断`）。
5. **认交接记录和修改建议**：开头写着“类型: 交接记录”的是库外 AI 写的，它的“已决定”要逐条回原件核对或问老板，核对前按待定处理；“类型: 修改建议”的，转成给老板的改动清单，确认后再改目标文件。
6. **列改动清单，等确认**：写进哪个文件的哪一段、写成什么、拟定状态（已确认 / 待确认）。改价格或规矩前，先在知识库里搜一遍旧值，把别处提到的地方一起列进改动清单，一次确认。清单长这样：

   ```text
   材料：00-收件箱/2026-10-28-某客户-当面.md
   事实：……
   已决定：老板答应 ××，××日前（原话：“……”）
   待定：……（谁提的，还没拍板）
   我的推断（AI 推断，仅供参考）：……
   对不上的地方：……（和 05-…/判断规则.md 第 N 条不一样），想问你：……
   要改的文件：
     1. 04-客户/某客户.md 往来记录 追加一条（待确认）
     2. ……
   你说“确认”我就写；只要部分就说“写 1、3”；说“不写”就什么都不动。
   ```
7. **写入**：照确认的清单写，每条带来源（原件路径）。往来记录只追加；答应过的事、顾虑、下一步追加新的一条，旧的按 `结构与规矩.md`“确认是什么意思”里的办法处理。新建的文件开头标“确认: 待确认”；往已确认的文件追加的，只在新行末尾标“（待确认）”，开头不动；要改已确认的内容，写在旧的下面等老板点头，不覆盖。老板答应的事，除了写进客户或项目文件：装了工作台的，提醒老板在工作台加待办；没装的，追加进 `06-项目/近期要事.md`。作品发出后的交接（平台、日期、链接）→ 在作品索引末尾只追加一行（编号、日期、平台、标题、原文位置），数据写明口径。新增文件后更新所在层 README 的索引。
8. **移原件**：问老板：“确认后，我把原件原样从 00-收件箱 移到 99-原始材料/聊天与通话/〈文件名〉，在 00-收件箱/README.md 的‘整理过的去了哪’记一行；不移，它留在收件箱，工作台和每周复盘会一直把它算成没整理的材料。”交接记录、修改建议移到 `99-原始材料/交接与建议/`；采访、录音转写放对应的文件夹。登记为“只读”的文件夹里的东西一律不移动。
9. **报告**：写了哪几个文件的哪一段（附链接），还有几条等老板定，下一份理不理。

写到哪（常见的几种）：

| 材料里的东西 | 写到哪 |
|---|---|
| 和客户说了什么 | 该客户文件的“往来记录”末尾；就地建图时写进 `<客户名>-往来记录.md` |
| 客户的顾虑、异议、拍板信号 | 该客户文件；再在 `04-客户/客户原话与顾虑.md` 追加一行（客户、日期、一句话，链到客户档案） |
| 老板做了一个判断（接不接、让不让、怎么补偿） | 05 对应工作的判断样本，作为候选，标待确认 |
| 和现有规则、价格、约定对不上 | `90-持续生长/待确认的发现.md` 追加一张卡，问老板 |
| 老板自己想让 AI 做的事 | 建库档案“老板最关心”或 `01-AI协作/协作偏好.md`，作为候选，标待确认 |
| 具体改工作台的需求 | 不写进各层；原件留给工作台 Skill 用，用完问老板移到 99 |
| 不知道放哪 | 先问老板，不新建文件夹 |

## 持续生长：只提“待确认的发现”

| 节奏 | 怎么触发 | 读什么 | 产出 | 老板花多久 |
|---|---|---|---|---|
| 事件后 | 成交、丢单、客诉、爆款、扑街、第一次做某事；老板说“复盘一下” | 这件事的往来和数据 | 1—3 条样本候选 | 5 分钟 |
| 每周 | 定时任务（见文末），或老板说“本周复盘” | 本周新增往来、改稿、收件箱 | 样本候选、冲突、快到期的提醒 | 10 分钟 |
| 每月 | 同上 | 一个月的记录、作品数据、已有样本 | 3—5 条结构性发现 + 月度复盘 | 30 分钟 |
| 每季 | 同上；生意明显变了随时做 | 关于我、各类规则、最近的维护报告 | 哪些过期、哪些还成立；生意变化访谈（见 `维护.md`） | 30 分钟 |

AI 找这些线索，找到就写成一张发现卡，只问不判：

1. 同一种选择反复出现（3 次以上）：可以提成一条规则。
2. 规矩写的是一样，记录里做的是另一样。
3. 某条规则的例外越来越多：可能要加条件。
4. 做出来的结果和当时想的不一样：判断可能要改。
5. 客户、项目、内容自己分成了几类：做法也该分开写。
6. 时间花的地方，和今年想做成的事对不上。
7. 到了复核时间的规则；老板常问、库里却找不到答案的问题。

护栏：只用库里的证据；每条写来源和样本量；不自动改规则、不自动升“已确认”；冲突只问不判；心理测试、性格推断不当证据；发现卡默认内部，不进对外内容。

确认以前，发现卡先写好“采纳后写到”（写进哪个文件哪一段、写成什么；不采纳会怎样）。这一行写成“- 采纳后写到：……”，放在“- 状态：”前面，行里不要再出现“状态：”（工作台按第一个“状态：”读状态）。确认以后：已采纳的写进 05（规则或样本）、02（做事方式）或作品库规律，协作方式的偏好写进 `01-AI协作/协作偏好.md`，卡上写去向；不采纳的留着，写理由，没有新证据不再提同一条。

复盘写成 `90-持续生长/复盘/<日期>-周复盘.md` 或 `<年-月>-月度复盘.md`：事实 / 判断 / 待确认分开写。同一天已经有这份周复盘，不覆盖：在原文件末尾追加“## 整理后补充”一段。还没整理的收件箱材料，复盘只数份数、说是谁的，不看内容下结论；和规则对不上的地方在整理时发现，整理以后的复盘再汇总。

## 体检（老板说“体检”，或每周一次）

先跑：

```bash
node "<本 Skill 文件夹>/scripts/check.mjs" "<知识库>"
```

建库收尾时加 `--stage quick`（快速版）或 `--stage connect`（接入已有资料），它会逐条说还缺什么，输出里有一行“体检结论：……”（打在 stderr，后面跟一句验收提醒）；`--brief` 只打这一行结论。标准结构的库用 `--stage connect` 会直接说“请用 --stage quick”，不出结论。

脚本查这些（只读）：

- 入口：`AGENTS.md` 在不在；维护标记全不全、是不是在第 1 行；有没有没填的占位；地图和“常见任务先读哪里”表在不在前 60 行，常见任务表里的路径都存在，每个生长模块都有一行路由；是否超过 100 行或 12 KB（超了说先挪哪一节）；旧版“知识库规则”段还在不在。`CLAUDE.md` 有没有 `@AGENTS.md`；除了 `@AGENTS.md` 有没有多写规矩（`.claude/CLAUDE.md`、`CLAUDE.local.md` 也看）。
- 固定层：9 层都在、都有 README（就地建图的按“目录对应”表找；只读、不读的文件夹不要求 README，但要在地图里）。`--stage quick` 时还查：只有说明、还没有内容的固定层（`00-收件箱`、`90-持续生长` 不算）；层里已经有文件了，README 还留着“（暂时没有）”的。
- 地图：`AGENTS.md` 地图里的文件夹都存在；磁盘上的层和模块都在地图里。
- 建库档案：有 `格式`、类型画像、老板最关心、启用的模块；表里的路径都存在（写“（计划）”的除外）；每个 1x 模块都在表里；没有没填的占位；写了演示日期的，格式对不对。
- 必读四份（`--stage quick`、`--stage connect`）：基本情况、协作偏好、生意总览、近期要事在不在（就地建图按目录对应换算位置）。
- README：头四行（装什么、不装什么、AI 什么时候读、谁来写）齐不齐；索引有没有漏文件、漏子文件夹；补索引补出来、还写着“（待补）”的行；5 份以上文件的文件夹有没有 README。
- 每份整理过的文件：5 个通用字段；“确认”“隐私”取值；“类型”在不在清单里（不在只提醒）；日期字段只能是日期、“未知”或“未定”；来源文件存在；客户、项目等类型的专属字段；待办格式；没填的模板占位、空段落。就地建图时，老板原有文件夹里的文件没有元信息只提醒，新建的层里缺元信息照样算错。
- 表格：格子数和表头对不上、格子里有 `|`。`AGENTS.md` 地图、建库档案的“目录对应”和“启用的模块”、客户层 README 的“建库快照”、`品牌与口吻.md` 的“不能说的话”、05 层 README 的“方法选择表”是程序要读的表，这几张算错；别的表只提醒。
- 原件清单（接入过的库才有）：老板原有文件有没有被改、被挪；接入收尾（`--stage connect`）时算错，平时只提醒——老板自己改是正常的。
- 链接：所有相对链接指向的文件都存在。
- 敏感信息：疑似密码密钥、手机号、身份证号、银行卡号（要过校验位，旁边有卡号、银行这类字样才算错，没有的只提醒）。整理稿里出现算错；原件（收件箱、原始材料）里出现只提醒，整理时别抄进整理稿。“密码：不存在这里”这类否定说法不算。证照、合同、录音这类原件（00、99 下的图片、PDF 等，或文件名带执照、合同、录音的）只提醒，问老板要不要留。
- 已确认的文件里还有几行等你点头：行末“（待确认）”和“AI 的看法”下的条目（只计数，在结果的 `summary.counts.pending_lines` 和 `pending_line_files` 里；任务手册讲规矩的括注不算）。
- 做内容、对外发东西的老板，有没有 `品牌与口吻` 和它的“不能说的话”表（只提醒）。
- 接入收尾（`--stage connect`）：原有文件里没做完的待办有没有抄进近期要事（只提醒）。

脚本之外再看三件，写进体检报告：到了“复核”时间的规则和样本；超过“文件怎么长大”阈值、该提议拆分的文件；云盘冲突副本（如 `客户 2.md`、`客户 (1).md`、`客户（1）.md`）：告诉老板，不合并、不进索引、不删。

体检报告在对话里给，三段大白话：**已经好的** / **我可以直接改的**（格式问题，你说“修”就修）/ **要你确认的**。到复核时间的规则和样本、该提议拆分的文件、冲突副本放进第三段。老板要留档，跑 `maintain.mjs --write`，报告新建在 `<90 层>/体检/`（类型 体检报告，见 `维护.md`）。查冗余、过期、积压、结构信号这些更深的维护，也看 `维护.md`。自己刚写完东西跑的体检（建库、整理、补访之后），格式问题直接修好再汇报，见 `结构与规矩.md`“写完就体检”。体检只出报告和建议，别的改动等老板确认。

## 用定时任务跑复盘和体检（可直接粘贴）

提示词每条只指向任务手册，不重复步骤。用 Claude Code 的，把 `$boss-kb` 换成 `/boss-kb`。

每周复盘：

```text
用 $boss-kb，在这个知识库里按 01-AI协作/任务手册/每周复盘.md 做本周复盘。只读上次复盘之后新增或改过的文件；只在 90-持续生长/复盘/ 新建一份、在 90-持续生长/待确认的发现.md 末尾追加；不改、不移、不删别的文件，不联网，不发任何消息。做完用三句话告诉我。
```

每周维护、每月结构复盘：提示词原文见 `维护.md` 的“定时跑”，照那里的粘贴，这里不另写一份。

月度复盘：

```text
用 $boss-kb，在这个知识库里按 01-AI协作/任务手册/每周复盘.md 做这个月的复盘，文件名写“年-月-月度复盘.md”。只读这个月新增或改过的文件；只在 90-持续生长/复盘/ 新建一份、在 90-持续生长/待确认的发现.md 末尾追加；不改、不移、不删别的文件，不联网，不发任何消息。做完用三句话告诉我。
```

（提示词里不用尖括号占位，免得抄进库里以后被体检当成没填的占位。）

建任务四步：

1. 在 Codex 定时任务里选这个知识库文件夹。知识库是 git 仓库时，选在本地项目里跑，不用 worktree：worktree 是一份副本，写进去的复盘不会出现在你的知识库里。
2. 粘提示词，选每周几、几点。
3. 建好当场点一次“立即运行”，看 `90-持续生长` 里有没有多出新文件。
4. 看“下次运行”显示的时间；第一次自动跑完，再对一下实际时间。有人遇到过显示的和实际差 8 小时，对不上就按差值调。
