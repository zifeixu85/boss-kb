# 梳理范例：四种常见的“已有体系”怎么对

配合 `梳理已有资料.md` 用。四个老板和他们的资料都是**虚构的**，只演示怎么看、怎么对、草案怎么写；真老板的文件夹以他实际的为准，不照搬这里的对应。

`--map` 的右边必须是一个现有文件夹，不能填文件名或多个位置。只有 CSV、随手记或多个资料目录时，保留对应的标准层，新写索引链接原文件；不搬、不改原件。只读和不读每个位置单独登记。

每个例子都按同一个顺序：原来长什么样 → 划范围 → 对应 → 我看到的习惯 → 工作台结构草案。

---

## 一、Obsidian 库，按“项目 / 领域 / 资源 / 归档”分

**谁**：林溪，独立品牌设计师，一个人加两个兼职。用 Obsidian 三年。

**原来长什么样**

```text
设计工作/                     ← Obsidian 库（有 .obsidian）
├── 00 Inbox/                 12 份，今天还在改
├── 01 Projects/              34 份：每个项目一个文件夹（「青柠咖啡 VI」「山野民宿 包装」…）
├── 02 Areas/                 51 份：客户/、报价/、作品集/、财务/
├── 03 Resources/             120 份：字体、灵感、教程摘录
├── 04 Archive/               310 份：结束的项目
├── Daily/                    420 份：每天一篇日记
└── Templates/                模板（带 {{date}}）
```

**划范围**：Daily 和 02 Areas/财务 → 不读（日记、财务，名字就像私人的，她也说别看）；04 Archive、03 Resources → 只读；00 Inbox、01 Projects、02 Areas 其余 → 接入。Templates 是模板，不提炼。

**对应**

| 知识库的层 | 她原来的位置 |
|---|---|
| 00-收件箱 | `00 Inbox` |
| 04-客户 | `02 Areas/客户` |
| 06-项目 | `01 Projects` |
| 03-生意 | 新建 `03-生意`，索引链接 `02 Areas/报价`、`02 Areas/作品集`；不把两处一起传给 `--map` |
| 99-原始材料 | 新建（她没有） |
| 只读 | `03 Resources`、`04 Archive` |
| 不读 | `Daily`、`02 Areas/财务` |

**我看到的习惯**

- 客户一人一篇，开头属性写 `status: 洽谈 | 进行中 | 已结束`，用标签 `#客户`。
- 项目一个文件夹，里面固定有「需求.md」「进度.md」「交付清单.md」；进度按日期往下追加。
- 待办散在各个「进度.md」里，写成 `- [ ] 周五前交第二稿`。
- 用双链很多（`[[青柠咖啡 VI/需求]]`）。

**工作台结构草案**

- 基础版：今日、日程、待办、项目、收件箱、知识库、设置。
- 项目：从 `01 Projects` 读，每个项目的下一步取「进度.md」最后一条。
- 客户跟进：要加。阶段用她的“洽谈 / 进行中 / 已结束”，客户从 `02 Areas/客户` 读。
- 待办：各「进度.md」里没做完的 `- [ ]` 抄进近期要事（写来源），以后新待办记在工作台。
- 首页先放：项目推进到哪、今天要做的、收件箱。
- 不加：经营看板（她没有每天的经营数）。

## 二、按客户和年份分的一堆文件夹

**谁**：老周，装修公司老板，十来个人。资料都在电脑“文稿”里，Word、Excel、Markdown 混着。

**原来长什么样**

```text
周记装饰/
├── 2024/  2025/                去年和前年的工地，按小区名分文件夹（只读）
├── 2026/
│   ├── 在施工/                  6 个工地文件夹：「锦绣花园 3-1201」…
│   └── 在谈/                    9 个客户文件夹：报价单.xlsx、量房记录.md、聊天记录.txt
├── 报价模板/                    价目表.xlsx、报价说明.md
├── 员工/                        工资表.xlsx、身份证复印件（不读）
└── 随手记.md                    一个大文件，啥都往里写，今天还在改
```

**划范围**：员工 → 不读（证件、工资）；2024、2025 → 只读；2026、报价模板、随手记 → 接入。

**对应**

| 知识库的层 | 他原来的位置 |
|---|---|
| 04-客户 | `2026/在谈`（一个文件夹一个客户） |
| 06-项目 | `2026/在施工`（一个工地一个项目） |
| 03-生意 | `报价模板` |
| 00-收件箱 | 新建 `00-收件箱`，索引链接原来的 `随手记.md`（只读，不移动内容） |
| 只读 | `2024`、`2025` |
| 不读 | `员工` |

**我看到的习惯**

- 客户的阶段就是文件夹：“在谈”→ 签了合同挪到“在施工”→ 完工挪进年份文件夹。阶段他嘴上叫“量房 / 出报价 / 签约 / 施工 / 验收 / 回款”。
- 报价都是 Excel，量房记录是 Markdown；聊天记录是从微信复制出来的文字。
- 待办全写在 `随手记.md` 里，没有格式。
- 两处对不上：价目表写“全包 1280 元/平起”，随手记里写“今年起 1380”。列出来问他，不替他选。

**工作台结构草案**

- 基础版一定有。
- 客户跟进：要加，阶段用他的“量房 / 出报价 / 签约 / 施工 / 验收 / 回款”；客户从 `2026/在谈` 读。
- 项目：每个工地一个项目，关键日子（开工、水电验收、完工）做成里程碑。
- 收件箱：他把聊天记录丢进来，AI 拆出“下一步、谁做、哪天前”再问他。
- 首页先放：该跟进的客户（在谈的 9 家）、项目推进到哪（6 个工地）。
- 以后再说：回款（他说“钱的事我自己记”）。

## 三、Notion 导出（Markdown + CSV）

**谁**：Mia，独立咨询顾问，客户都记在 Notion 的数据库里。

**原来长什么样**（Notion 里点“导出 → Markdown & CSV”，解压后整包放进 `99-原始材料/导入-Notion-2026-10-15/`，原样不动）

```text
99-原始材料/导入-Notion-2026-10-15/
├── 客户 3f2a….csv              一行一个客户：名称、阶段、来源、下次联系、合同额
├── 客户 3f2a…/                 每个客户一篇页面（.md）
├── 项目 9b1c….csv              一行一个项目：名称、客户、状态、截止
├── 会议纪要/                   每次会议一篇
└── 读书笔记/                   与工作无关（只读）
```

**划范围**：读书笔记 → 只读；其余接入。导出包整个放在 99 层，不拆、不改名（文件名里的长串编号也留着）。

**对应**

| 知识库的层 | 她原来的位置 |
|---|---|
| 04-客户 | 新建 `04-客户`，建库快照的“文件”列链接原 CSV 和对应页面，另写行里的客户名称 |
| 06-项目 | 新建 `06-项目`，索引链接原项目 CSV，注明每个项目所在行 |
| 05-方法与判断 | 没有（缺口，以后补访） |
| 只读 | `读书笔记` |

**我看到的习惯**

- 客户阶段是表里的一列：“线索 / 初聊 / 提案 / 签约 / 交付中 / 已结束”。
- 每次会议一篇纪要，标题是“日期 + 客户”，里面有“下一步”。
- 以后她还会在 Notion 里继续记：导出是一次性的，过一阵要再导一次（登记进建库档案的“导入批次”）。

**工作台结构草案**

- 基础版一定有。
- 客户跟进：要加，阶段用她表里那六个；第一次从 CSV 导入（老板确认过的行），以后新客户在工作台记。
- 项目：从项目 CSV 导入。
- 收件箱：会议纪要丢进来，AI 拆出下一步和待办。
- 首页先放：该跟进的客户、项目推进到哪。
- 提醒她：Notion 和工作台会有两份客户表。定一个“以哪边为准”（她说以后在工作台记，Notion 只留旧的）。

## 四、飞书文档和多维表格导出

**谁**：阿珍，三家烘焙店的老板，店长们在飞书里填表。

**原来长什么样**（飞书文档导出成 Word 或 Markdown；多维表格导出成 Excel / CSV，放进 `99-原始材料/导入-飞书-2026-10-15/`）

```text
99-原始材料/导入-飞书-2026-10-15/
├── 门店日报.xlsx               三家店每天的营业额、单数、损耗（店长填）
├── 会员.xlsx                   会员名单和储值（标私密）
├── 新品计划.docx               秋冬新品、上新时间
├── 店长周会/                   每周一篇纪要
└── 员工排班.xlsx               只读
```

**划范围**：会员、员工排班 → 只读（会员表照实存，标私密）；其余接入。

**对应**

| 知识库的层 | 她原来的位置 |
|---|---|
| 03-生意 | `新品计划.docx`（提炼成产品与上新） |
| 06-项目 | 新品上新做成项目（从新品计划里来） |
| 10-渠道与经营（生长模块） | `门店日报.xlsx` 的口径写在这里，数据本身在工作台 |
| 只读 | `会员.xlsx`、`员工排班.xlsx` |

**我看到的习惯**

- 每家店每天一行：日期、门店、营业额、单数、损耗；周会纪要里有“问题 / 措施 / 谁跟进”。
- 她最在意：哪家店昨天不对劲、新品什么时候上。
- 客户是散客，不在维护单个客户：**不加客户跟进**。

**工作台结构草案**

- 基础版一定有。
- 项目：秋冬新品上新做成项目，上新日做里程碑。
- 经营看板：以后加。先按 `数据来源.md` 核对门店日报“一行代表什么”（一天一家店），再立项对焦；搭建时先不放。
- 收件箱：店长周会纪要丢进来，拆出“谁跟进、哪天前”。
- 首页先放：项目推进到哪（新品）、今天要做的、收件箱里的周会要点。
- 不加：客户跟进（散客，没人在维护单个客户）。
