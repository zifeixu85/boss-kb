# 定期维护：每周体检、每月结构复盘、生意变了再访谈

知识库用久了会长乱：同一个客户建了两份、价格在三处写全、半年没动的规矩还当真用、收件箱越堆越多。维护分三档，越往后越需要老板参与。

| 档 | 多久一次 | 谁动手 | 产出 | 改不改知识库 |
|---|---|---|---|---|
| 每周体检 | 每周一次（可以定时） | 脚本找信号，AI 读报告 | `90-持续生长/体检/<日期>-维护报告.md` | 不改，只新建这份报告 |
| 每月结构复盘 | 每月一次 | AI 读报告和这个月新增的内容 | 报告里的“本月结构建议” | 老板确认后才改 |
| 生意变化访谈 | 每季度一次，或生意明显变了 | AI 问，老板答 | 更新后的类型画像、老板最关心、模块和地图 | 老板确认后才改 |

路径都按建库档案的“目录对应”换算；就地建图的库，“原有·不读”的文件夹不进去，“原有·只读”的只计数。

## 每周体检

1. 先只读跑一次，看有哪些信号：
   ```bash
   node "<本 Skill 文件夹>/scripts/maintain.mjs" "<知识库>"
   ```
   想留一份报告就加 `--write`。它只在 `<90 层>/体检/` 新建一份报告，同名时自动加 `-2`，别的文件一个都不改。示例库不写报告。日期默认按今天算（示例库按演示日期），要按别的日子算加 `--date 2026-10-27`。报告开头是“类型: 体检报告”“确认: 待确认”，不进索引；末尾两节“本月结构建议”“下次访谈可以问”是留给 AI 补写的。
2. 脚本按六类找信号：

   | 类 | 查什么 | 默认的线 |
   |---|---|---|
   | 冗余 | 同类档案里重名或别名重了；一份客户档案被两个分组都收了；整理稿之间有一模一样的大段文字 | 去掉空白后 40 字以上的段落 |
   | 问题 | 体检的错误和提醒；断掉的链接（普通链接、双链都查）；标“可公开”的文件，来源里却有“私密”的文件 | 照体检 |
   | 过期 | “更新”太久没动（任务手册、原件清单、变更记录、复盘、经营复盘、代表作、往来记录、发现清单、体检报告这些本来不随时间更新的不算）；`确认: 已过期`；“复核”日期已经过了（“复核”写的是事件，如“春节后”，只列出来不算） | `--stale-days 90` |
   | 积压 | 收件箱里放太久的材料（天数依次按“更新”、日期、文件名开头的日期、修改时间算）；待确认越堆越多；待确认的发现没处理（“状态”不是已采纳、采纳、不采纳开头的都算） | `--inbox-days 14` |
   | 体量 | 太长的文件；往来记录太多；一个文件夹里直接放了太多文件；AGENTS.md 快到上限 | 300 行、20 条、30 份、10 KB（上限 12 KB） |
   | 结构信号 | 固定层只有 README；生长模块只有 README；“（计划）”的模块放了太久；根目录有地图里没写的文件夹 | 计划超过 30 天 |

3. AI 读报告，翻成白话分三段说给老板：
   - **已经好的**：一两句话就够；
   - **我可以直接改的**：格式、索引、断链、字段写法这类不改意思的，列清单，老板说“改”再改；
   - **要你确认的**：合并重复的档案、过期的内容留不留、隐私标没标对、收件箱里的材料怎么归。
   不要把脚本的原话整段贴给老板。
4. 改的时候照 `结构与规矩.md` 的规矩：原话和原件只追加；AI 整理的当前结论经确认后更新，旧结论留在文末“历史”；合并重复的档案时，新内容并进留下的那一份，另一份开头改成 `确认: 已过期`，正文第一行写“已并入 [那一份]”，不删文件；移动文件之前先问。

脚本把这几种放进“我可以直接改的”：缺文件开头、缺“类型 / 更新 / 确认 / 隐私”这类格式问题，日期和字段写法、索引漏行、表格错列，能找到新位置的断链，AGENTS.md 偏大，90 层还是空的（说“本周复盘”就行）。这些算要你确认：疑似密码、密钥；有手机号、证件号的文件没标私密（照实记没问题，问你标不标私密）；缺“来源”或某类文件自己的字段（如客户的联系人）；确认、隐私、阶段、状态的值写得不对；还没填的占位（要采访才能填）；内容缺口；地图里没写的文件夹（里面的文件哪怕只是格式问题，也先问）。

**容易误报的**，看一眼再报：
- 示例库、刚建好的库，故意留着没整理的收件箱和大量待确认，是正常的；
- 同名档案只认名称或别名完全一样：两位不同的“王总”会被报，“云杉物流”和“云杉物流有限公司”反而抓不到；
- 有意抄一份的清单（比如“老板最关心”和“每天早上想看到”内容一样）也会被报成重复段落，问老板要不要只留一处、另一处写链接；引用块和“来源”小节不查重复；
- 客户层 README 的“分组”写法和文件夹名不一样时，可能被报成“两个分组都收了”；
- 老板原有的笔记没有“更新”字段，按修改时间算，可能显得很旧；
- 双链只写文件名、而库里有同名文件的，会被报成断链或有歧义，让老板挑一个；Obsidian 里故意先占位、以后再建的链接也会被报；
- 来源写了采访记录（整份私密）的“可公开”文件会被报成隐私对不上，多半看一眼就能放行；
- “地图里没写”的文件夹会在“问题”和“结构建议”里各算一次。

## 每月结构复盘

在每周体检的基础上，再读这个月新增的东西：往来记录、收件箱里整理过的材料、工作台写回的发现、`90-持续生长/待确认的发现.md`。看这几件事：

1. **该拆的**：太长的文件、往来记录超过 20 条的客户（按规矩拆成文件夹：档案.md + 往来记录.md）、文件太多的文件夹（按分组或业务线分）。
2. **该并的**：重复的档案、内容很少又总是一起读的几份文件。
3. **该长出来的**：收件箱和往来记录里反复出现、又没有地方放的话题（比如开始做直播、有了供应商），说得出 3 件以上真事的，建议新开一个 1 开头的模块；不够的先登记成“（计划）”。
4. **该收起来的**：长期没人读、也没再更新的模块或文件夹，建议在建库档案里标“暂停”，不删。
5. **生意变了没有**：新产品、新渠道、新类型的客户、团队变化、价格变化。变化大的，约一次生意变化访谈。

把建议写进当月报告的“本月结构建议”一节：每条写“建议怎么改 · 为什么 · 改了以后哪里会变”。老板逐条确认，再按 SKILL.md 对应的模式去做（加模块、拆文件、改地图）。改了 AGENTS.md 的地图，提醒老板新开对话才生效。

## 生意变化访谈

什么时候做：每季度一次；每月复盘看出生意明显变了；老板自己说“最近生意变化挺大”。

开场说清：“这次 15—20 分钟，聊聊这几个月生意有什么变化，我按你说的调整知识库的结构。一次问一题，答完我先复述，你确认了再改。”

先读建库档案的类型画像、老板最关心、启用的模块，以及最近一份维护报告，再从下面挑 5—8 题，已经知道的只确认：

1. 这几个月，钱主要从哪来，和以前比有变化吗？
2. 有没有新开始做、或者不再做的产品、渠道、业务？
3. 客户有什么变化？新来的是什么样的人，走了的是为什么？
4. 团队、合作伙伴有什么变化？谁现在管什么？
5. 你现在最操心的 1—3 件事是什么，和上次说的一样吗？
6. 哪些事现在想交给 AI 做，上次说的还想不想？
7. 有没有哪条规矩、价格、做法已经不这么干了？
8. 知识库里有没有哪部分你觉得用不上、或者总找不到？

问完一屏复述，再列改动清单：
- 类型画像、老板最关心要不要改；
- 要加、要暂停哪些模块；
- AGENTS.md 的地图和常见任务怎么改；
- 哪些规矩、价格标“已过期”，新说法写在旧的下面。
老板说“确认”再写。原话照常记进 `99-原始材料/采访记录/<日期>-生意变化访谈.md`，在建库档案“已完成”记一行。

## 定时跑

Skill 只管每次维护怎么做；到点叫它的，是各家工具自带的定时功能。自动跑的时候**只新建报告**，不改、不移、不删已有文件；改动都等老板看完报告、说“确认”再做。

提示词原文（只在这里维护一份，别处引用这里）：

每周维护：

```text
用 $boss-kb 做每周维护：跑 maintain.mjs，带 --write，只新建一份维护报告；不改、不移、不删其他文件，不联网，不发任何消息。最后用三段话告诉我：已经好的、你可以直接改的、要我确认的。
```

每月结构复盘：

```text
用 $boss-kb 做每月结构复盘：先跑 maintain.mjs，带 --write，只新建一份维护报告；再读这个月新增或改过的往来记录、整理过的材料和待确认的发现，把结构建议写进这份报告的“本月结构建议”，可以问我的写进“下次访谈可以问”；不改、不移、不删其他文件，不联网，不发任何消息。最后用三段话告诉我结果。
```

（提示词里不用尖括号占位，免得抄进库里以后被体检当成没填的占位。用 Claude Code 的，把 `$boss-kb` 换成 `/boss-kb`。）

- **Codex App**：在知识库这个项目里新建一个定时任务（界面上可能叫“自动化”），粘上面的提示词，选每周或每月一次。知识库是 git 仓库时选在本地项目里跑，不用 worktree：worktree 是一份副本，写进去的报告不会出现在你的知识库里。建好当场点一次“立即运行”，看 `体检/` 里有没有多出一份报告。
- **Claude Code**：用它在本机跑的定时任务，提示词照上面写（Claude Code 本机定时任务的具体用法还没实测）。云端跑的定时任务读不到你电脑上的知识库，不要用。
- **搭了工作台的**：可以让工作台每天整理时顺便提醒“这周还没体检”。
- **没有定时功能**：每周一自己说一句“知识库体检”就行。

建定时之前跟老板说一声：定时的那次对话也会把用到的内容发给模型服务商，跟平时一样。
