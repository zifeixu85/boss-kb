# 进内容：先拆、再问、一张清单、分头写

新内容进知识库时都照这个做：
- 老板丢进来的聊天、会议纪要、通话转写、客户材料；
- 老板说“和某某聊了”“定了”“办完了”“发了”；
- 补访里冒出来的新进展；
- 库外项目写回；
- 每周复盘时收件箱里的材料。

为什么：只把原文追加进往来记录，下一步、谁做、哪天前、谁拍板都还散在原文里，老板得自己再读一遍，待办也就漏了。进内容时先判断，把要老板定的在对话里一次问清，确认后各写各的地方。

## 六步

1. **认出来**：是什么、哪天、谁在场、说的是哪位客户或哪个项目。认不出就问，不猜。
2. **拆**：按下面 7 类拆。原话照旧写进往来记录一行（附来源），往来记录只是留痕，不代替这 7 类。
3. **先问**：缺的、拿不准的合成一次问，最多 3 个问题，每个给默认选项。老板答“都按默认”就行。
4. **一张清单**：拆的结果、要写的地方、要建的待办，列成一张给老板看。老板说“确认”就全写，说“写 1、3”就只写这几条。
5. **分头写**：照清单写进知识库各小节；装了工作台的，待办、跟进用工作台的命令建，写上谁做、截止。
6. **汇报**：一句话说清改了哪几处、建了哪几条待办、还有哪几个问题等老板回答。

## 7 类

| 类 | 拆什么 | 写到哪 | 装了工作台以后 |
|---|---|---|---|
| 状态变化 | 客户阶段、项目进度、卡在哪、在等谁，有没有变 | 客户、项目文件开头和“当前状态” | 阶段、下次跟进在工作台改（改阶段要写原因）；知识库只在往来记录里记一句 |
| 决定 | 定了什么，谁定的：老板亲口说的、别人提的、还是 AI 推断的；带原话出处（逐字稿带时间戳） | 项目“关键决策”，客户“当前判断与下一步”。老板亲口说的照写并注明出处；别人提的、推断的，问过再写 | 同左 |
| 下一步 | 新的下一步是什么；替代了哪条旧的 | 客户“当前判断与下一步”，项目“下一步”；旧的照规矩不覆盖，写在旧的下面 | 同左，日期以工作台为准 |
| 待办 | 做什么、谁做（老板、团队里谁、对方）、哪天前；“周四前”换成日期 | 没装工作台：`06-项目/近期要事.md`，一行一条，写上谁做 | 用工作台命令建，带谁做和截止（命令以 `工作台/README.md` 写的为准） |
| 里程碑和日期 | 上线、交付、付款节点、活动日 | 项目“关键日期” | 也加进工作台的项目里程碑 |
| 要老板拍板的 | 还没人定、又必须老板定的事 | 先在对话里问，附 AI 的建议和默认选项；问不到的写进报告“等你回答”，或 `90-持续生长/待确认的发现.md` | 同左 |
| 答应、顾虑和信号 | 我们答应了什么（给谁、什么、哪天前）；对方担心什么；买不买的信号；和价目、判断规则对不上的地方 | 客户“答应过的事”“顾虑”；`04-客户/客户原话与顾虑.md` 追加一行；对不上的写发现卡 | 答应的事同时建一条待办 |

几条规矩：
- “考虑一下”“再看看”不算决定，阶段也不往前走。
- 会议里分清三种：老板当场拍板的、别人提议还没人拍板的、等对方给数字才能定的。后两种写清谁提的、等什么，不写成决定。
- 报价、价格、交期、补偿、签约、回款、对外承诺，不管多确定，在清单里单独列出，老板确认才写。
- 改价格或规矩前，先在库里搜旧值，把别处提到的地方一起列进清单。
- 老板说的“周四前”“下周”，按材料的日期换成具体日期，换不出来就问。

## 问法

- 一次问完，最多 3 个；先问会改结果的：谁做、哪天前、这件算不算定了。
- 每个问题给默认，老板一个字就能答。

```text
想问你 3 件（括号里是我的默认）：
1. 两套报价方案由小周做、10/30 前给你看？（是）
2. 王总说“下周跟财务碰一下”，算对方还没定，阶段先不动？（是）
3. 送货上门是你答应的，还是我从语气里推断的？（推断，先不写进答应过的事）
```

## 清单长这样

```text
材料：00-收件箱/2026-10-28-云杉物流-电话.md（10/28，王总，云杉物流）
一句话：云杉要两套年会礼盒报价，下周和财务定预算。
状态变化：云杉 需求确认 → 方案中（你确认后改）
决定：
  - 你定的：起订 50 份不变（原话：“50 份起，这个不能松”）
  - 王总提的：想要一款 300 元以内的（还没定）
下一步：10/30 前发两套方案（替代原来的“等王总给人数”）
待办：
  1. 做两套报价方案｜小周｜2026-10-30
  2. 打电话问预算定了没｜你｜2026-11-04
里程碑：年会 2026-12-20（新）
要你拍板：300 元以内那款要不要做？（我的建议：做，用现成礼盒换茶）
答应 / 顾虑：答应 10/30 前发方案；王总担心送货赶不上
对不上的地方：无
要写的地方：
  1. 04-客户/云杉物流.md 往来记录 追加一条
  2. 同一份 答应过的事 追加一条（待确认）
  3. 同一份 当前判断与下一步 追加新的下一步（待确认）
  4. 待办 1、2：<工作台命令，或追加进 06-项目/近期要事.md>
问你：（上面 3 个问题）
你说“确认”我就照这张清单写；只要部分就说“写 1、3”；说“不写”就什么都不动。
```

## 快的时候：记一笔

老板一句话（“和云杉王总聊了，下周给报价”）也照六步，只是更短：
- 往来记录那一行直接拟好；
- 同一条回复里拆出下一步、待办（谁、哪天）、答应的事，缺的问一句；
- 一张小清单，老板确认后一起写。

不要记完往来就结束，也不要只回一句“去工作台加个待办”。

## 老板不在对话里时

定时任务、库外项目自动写回、后台导入时，没人可问：
- 往来记录、原件照规矩放；
- 7 类照拆，写进这次的报告或交接记录对应几节；
- 要建的待办、要拍板的事，攒进报告的“等你回答”一节，每条带判断和默认建议。不替老板建待办，不改阶段和状态。
- AI 自己放进 `00-收件箱` 的材料（老板给的原件不改），文件末尾附一节 `### AI 的看法（<称呼>还没看过）`：这是什么、建议写到哪、默认怎么办。老板下次说“整理一下”时照六步走。
